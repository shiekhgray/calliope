### Bug fixed: skip-every-other-track in album playback

**Symptom**: When playing an album straight through, the player skipped every other track (played tracks 1, 3, 5, … instead of 1, 2, 3, …).

**Root cause**: React 18 `<StrictMode>` double-invokes functional state updaters to surface side-effect bugs. The `onended` handler in `PlayerContext.jsx` dispatched `setQueueIndex` *inside* `setQueue`'s updater function. StrictMode's double-invocation of `setQueue`'s updater produced two `setQueueIndex` dispatches; React processed them sequentially with each seeing the result of the previous, so `queueIndex` incremented by 2 on every track end. `_extendWithRadio` had the same nested-setState pattern.

**Fix** (`web/src/player/PlayerContext.jsx`, commit `ed743cb`):
- Added `queueRef`, `queueIndexRef`, `currentTrackRef` — refs that mirror their state counterparts.
- Added `_setQueue`, `_setQueueIndex`, `_setCurrentTrack` wrappers that update both ref and state atomically.
- Rewrote `onended` to read directly from refs and make flat (non-nested) setter calls.
- Rewrote `_extendWithRadio` the same way.
- Updated `skipNext`, `skipPrev`, `togglePlay`, `_loadTrack`, `playTrack` to use the wrappers.
- `skipPrev` now uses `audio.currentTime` directly instead of the `progress` state variable (ground truth).

**Key gotcha for the future**: Any time you call `setState` inside another `setState`'s updater function, StrictMode will double-fire the inner dispatch. The pattern to avoid: `setOuter(outerState => { setInner(innerState => { ... }); return outerState })`. The safe pattern: read from refs, call setters flat.
