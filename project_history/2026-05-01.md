## Session 1

### What shipped

**Qobuz zip import support**

Qobuz downloads use a different zip structure than Bandcamp or Amazon:
- Single subdirectory named `Artist - Album/` (not `Artist/Album/`)
- Tracks are FLAC, not MP3 — no cover art included
- Zip filename is arbitrary (not `Artist - Album.zip`)

Three changes to support this end-to-end:

1. **`scripts/qobuz_import.py`** — standalone CLI importer (host-side). Parses artist/album from the subdirectory name, extracts each FLAC to a temp file, transcodes to MP3 V0 via ffmpeg, writes to the music library. Supports `--dry-run`. Used to import the first Qobuz album manually (`Yelle - Pop-Up`, 12 tracks).

2. **`api/app/routers/import_music.py`** — added Qobuz format detection and `_extract_qobuz()` to the web import pipeline. Detection: one-level audio entries (`len(parts) == 2`) with a ` - ` in the subdirectory name. Transcodes via ffmpeg subprocess with a temp dir. Graceful error if ffmpeg not found in the container.

3. **`api/Dockerfile`** — added `ffmpeg` to the apt-get install list (Ubuntu 24.04). Rebuilt and restarted.

### Key decisions

- **Transcode to MP3 V0 rather than store FLAC**: keeps the library format-consistent (MP3/M4A/WAV) and avoids scanner changes. V0 VBR is ~245kbps — transparent quality, reasonable file size.
- **Temp dir for ffmpeg**: FLAC bytes live in memory (from the zip); ffmpeg needs filesystem I/O. `tempfile.TemporaryDirectory` handles cleanup automatically even on failure.
- **Qobuz detection order**: one-level before Bandcamp (flat) to avoid ambiguity. Amazon (two-level) is already first.

### Gotchas

- ffmpeg is not in the Fedora base repos — requires RPM Fusion. Installed on host for the CLI script; installed inside the Docker image via Ubuntu's standard apt repo (no extra config needed there).
- Qobuz zip files don't contain cover art. The album will scan without art until a `Folder.jpg` is added manually or via the album art upload feature.

### DB / infra changes

None — no migrations, no nginx changes. API image rebuilt.

## Session 2

### What shipped

Nothing deployed. Session was design/planning work.

**Track Credits PRD** (`prd/track-credits.md`)

Investigated why Lights collaboration albums (with i_o, GUNSHIP, ARMNHMR) weren't surfacing on the Lights artist page. Root cause: `track_artist_id` is a single FK — can only credit one artist per track — and the `compilations` endpoint additionally restricts to VA-owned albums, so non-VA collab albums were completely invisible.

Designed a many-to-many credits system. PRD covers:
- Two new tables: `album_artists (album_id, artist_id)` and `track_credits (track_id, artist_id)`
- Replaces `track_artist` / `track_artist_id` entirely (migration backfills, then drops both columns)
- Artist page gains a "Singles, Remixes and Collaborations" section (replaces "Appears On")
- "Albums" section queries via `album_artists` instead of `album.artist_id`
- Credit management UI on album page: per-track `+` / chip-remove, owner-only, artist search against existing artists
- Album-level primary artist management at album header

### Key decisions

- **Two tables over one with a role field**: `album_artists` (primary album-level credit) + `track_credits` (featured/guest per track) rather than a single `track_credits (role)` table. Cleaner semantics — owning an album vs guesting on a track are different intents. Role field muddled into a single table creates edge cases (e.g., accidentally marking 13 of 14 tracks as co-artist).

- **Don't fight ID3 tags**: user doesn't want to retag MP3 files. Scanner keeps writing `album.artist_id` from the albumartist tag forever. Combined-credit artist entries ("i_o & Lights") are hidden from the artist list by changing the `GET /artists` query: show artists with `album_artists` entries OR direct unattributed albums. Once a combined-credit album is claimed via `album_artists`, the combined-credit artist has no qualifying albums and drops off the list naturally — no deletion needed.

- **`album.artist_id` stays for display only**: scanner keeps it as the authoritative display name for album cards. `album_artists` drives navigation. Cleaner than trying to suppress scanner writes.

- **RAC's *Boy* as the test case**: a producer album where every track has a different featured vocalist. Currently not supported by the VA-only compilations mechanism. The new credits system handles it cleanly (album_artists → RAC; track_credits → each vocalist).

- **Manual credits via UI, no scanner automation**: library isn't growing fast enough to warrant ID3 parsing of combined artist names (which would require heuristics for "A & B", "A feat. B", etc.).

### Gotchas

- **Temporary DB state**: during exploration, ran `UPDATE tracks SET track_artist_id = 149 WHERE id IN (2893–2906, 2915, 2916)` to tag Lights on the collab tracks. This doesn't currently surface on Lights' page (compilations endpoint requires VA album ownership). Migration 0008 will backfill `track_artist_id` → `track_credits`, so this state is handled automatically. No cleanup needed before the migration.

- **Edit was interrupted**: `artists.py` compilations endpoint edit was started but rejected before writing — the file is unchanged from before this session.

### DB / infra changes

- `tracks.track_artist_id` set to 149 (Lights) on 16 rows: track ids 2893–2906 (i_o & Lights / Warehouse Summer), 2915 (GUNSHIP collab), 2916 (ARMNHMR collab). Live in prod. Will be superseded by migration 0008.

## Session 3

### What shipped

**Track Credits — full implementation** (`prd/track-credits.md`)

Complete many-to-many artist attribution system. All code written; migration not yet applied to production.

**Migration 0008** (`api/alembic/versions/0008_track_credits.py`):
- Creates `album_artists (album_id, artist_id)` and `track_credits (track_id, artist_id)` tables with composite PKs and `ON DELETE CASCADE` FKs
- Backfills `album_artists` from all existing `albums.artist_id` rows
- Backfills `track_credits` from `tracks.track_artist_id` (the 16 hand-edited rows from Session 2)
- Drops `track_artist` and `track_artist_id` columns from `tracks`
- Has a reversible `downgrade()` (best-effort backfill)

**API changes:**
- `GET /artists` — new filter: shows artists with `album_artists` entries OR unattributed albums. Combined-credit ghost entries ("i_o & Lights") drop off automatically once their albums are claimed.
- `GET /artists/{id}/albums` — now queries via `album_artists` JOIN; returns album's actual `artist_name` from `album.artist_id` (not the queried artist's name — fixed a subtle mismatch for collaboration albums).
- `GET /artists/{id}/compilations` — now queries via `track_credits` JOIN with `NOT EXISTS album_artists` exclusion; replaces the old VA-only compilation query.
- `GET /albums/{id}` — each track now includes `credits: [{artist_id, artist_name}]` fetched in one query.
- New router `credits.py`: `GET /albums/{id}/artists`, `POST /albums/{id}/artists`, `DELETE /albums/{id}/artists/{artist_id}`, `POST /tracks/{id}/credits`, `DELETE /tracks/{id}/credits/{artist_id}` — all mutating endpoints owner-only (user_id == 1).
- Scanner (`scan.py`) — removed `track_artist`/`track_artist_id` writes; credits are now manual-only.

**Web changes:**
- `AuthContext.jsx` — added `userId` (persisted in localStorage as `user_id`; fetched via `GET /auth/me` on login and for existing sessions that pre-date this storage key).
- `AlbumPage.jsx` — new components: `ArtistSearchInput` (debounced search dropdown), `CreditChip` (feat. link; owner gets confirm-to-remove), `TrackCredits` (per-track credit row with owner `+` button), `AlbumCreditsSection` (collapsible owner-only section for album-level credits). Removed old `isCompilation` / `track_artist` column logic.
- `ArtistPage.jsx` — "Appears On" heading renamed to "Singles, Remixes and Collaborations".

### Key decisions

- **`album.artist_id` kept for display, `album_artists` drives attribution**: scanner keeps writing `album.artist_id` from the albumartist tag — that value shows on album cards. Artist page queries go through `album_artists`. No two-source-of-truth conflict because they're used for different things.
- **`GET /artists/{id}/albums` returns album's actual `artist_name`**: fixed the agent's initial output, which returned the queried artist's name. For collaboration albums, you want the card to show "i_o & Lights" (the album's display artist), not "Lights" (the page you're on).
- **`AlbumCreditsSection` lazy-fetches `GET /albums/{id}/artists`**: the album credits panel only loads when opened, keeping the initial album page load clean.

### Gotchas

- The web agent initially left `isCompilation` / `track.track_artist_id` references in AlbumPage — those fields are dropped by the migration. Had to remove that block manually after reviewing the output.
- The API agent didn't implement `GET /albums/{id}/artists` (only POST/DELETE), but the web `AlbumCreditsSection` calls it. Added the GET endpoint to `credits.py` manually.

### DB / infra changes

**None applied yet.** To deploy:

```
docker compose exec api alembic upgrade head
```

Then run post-migration manual cleanup (add `album_artists` rows for the known collab albums — see `prd/track-credits.md` cleanup table).

**Singles & EPs PRD** (`prd/singles.md`)

Designed a release-type system to distinguish singles and EPs from full albums in the data model and on the artist page. Added to `.todo`.

Key spec decisions:

- **`album_type` column on `albums`** (`'album'` default | `'ep'` | `'single'`). Three distinct values in the DB even though EPs and singles share one display section — keeps the data precise for future splits.
- **Artist page section order**: Top Tracks → Albums → Singles & EPs (new, conditional) → Appears On → Missing Releases.
- **"Singles, Remixes and Collaborations" → "Appears On"**: the current compilations-appearance section gets renamed to free up "Singles" terminology for the new feature.
- **Single card**: same `.album-card` layout with an always-visible ▶ overlay (bottom-right of art). Card art/title still links to `/albums/{id}`. Shows a "Single" / "EP" badge in the info row.
- **`GET /artists/{id}/singles`**: new endpoint; embeds `first_track` in each album record so the frontend can call `playTrack()` without a second fetch.
- **`PATCH /albums/{id}/type`**: owner-only; AlbumPage gets a clickable type-cycle pill for the owner.
- **Type badge shown per card** in the Singles & EPs section so single vs EP is still visible despite sharing a section.
- Migration number: **0009**.

### Key decisions

- **Lump EPs and singles in the UI, differentiate in the DB**: avoids two sparse sections (a small library might have only 1–2 singles and 1 EP at a time). The badge on each card preserves the distinction visually.
- **No auto-detection by track count**: too error-prone. Manual labeling only, via the AlbumPage owner UI.
- **Inline play overlay always visible** (not hover-only): artist page is a browsing context; hover-only is fine for desktop but awkward for touch and for discoverability.

### Spacebar clarification

Investigated `useSpacebarPlayback.js` (`web/src/hooks/useSpacebarPlayback.js:22`): when `isPlaying === null`, spacebar calls `playTrack(track)` (single-track form) with just `topTracks[0]` — not a queued list. The page does not "work its way down" through top tracks in order; after that one track, radio mode kicks in. Singles do not need to interact with spacebar registration.

### DB / infra changes

None. No migrations, no nginx changes.
