## Session 1

### What shipped

**Qobuz zip import support**

Qobuz downloads use a different zip structure than Bandcamp or Amazon:
- Single subdirectory named `Artist - Album/` (not `Artist/Album/`)
- Tracks are FLAC, not MP3 — no cover art included
- Zip filename is arbitrary (not `Artist - Album.zip`)

Three changes to support this end-to-end:

1. **`scripts/qobuz_import.py`** — standalone CLI importer (host-side). Parses artist/album from the subdirectory name, extracts each FLAC to a temp file, transcodes to MP3 V0 via ffmpeg, writes to the music library. Supports `--dry-run`. Used to import the first Qobuz album manually (`Yelle - Pop-Up`, 12 tracks).

2. **`api/app/routers/import_music.py`** — added Qobuz format detection and `_extract_qobuz()` to the web import pipeline. Detection: one-level audio entries (`len(parts) == 2`) with a ` - ` in the subdirectory name. Transcodes via ffmpeg subprocess with a temp dir. Graceful error if ffmpeg not found in the container.

3. **`api/Dockerfile`** — added `ffmpeg` to the apt-get install list (Ubuntu 24.04). Rebuilt and restarted.

### Key decisions

- **Transcode to MP3 V0 rather than store FLAC**: keeps the library format-consistent (MP3/M4A/WAV) and avoids scanner changes. V0 VBR is ~245kbps — transparent quality, reasonable file size.
- **Temp dir for ffmpeg**: FLAC bytes live in memory (from the zip); ffmpeg needs filesystem I/O. `tempfile.TemporaryDirectory` handles cleanup automatically even on failure.
- **Qobuz detection order**: one-level before Bandcamp (flat) to avoid ambiguity. Amazon (two-level) is already first.

### Gotchas

- ffmpeg is not in the Fedora base repos — requires RPM Fusion. Installed on host for the CLI script; installed inside the Docker image via Ubuntu's standard apt repo (no extra config needed there).
- Qobuz zip files don't contain cover art. The album will scan without art until a `Folder.jpg` is added manually or via the album art upload feature.

### DB / infra changes

None — no migrations, no nginx changes. API image rebuilt.

## Session 2

### What shipped

**Track Credits PRD** (`prd/track-credits.md`)

Investigated why Lights collaboration albums (with i_o, GUNSHIP, ARMNHMR) weren't surfacing on the Lights artist page. Root cause: `track_artist_id` is a single FK — can only credit one artist per track — and the `compilations` endpoint additionally restricts to VA-owned albums, so non-VA collab albums were completely invisible.

Designed a many-to-many credits system. PRD covers:
- Two new tables: `album_artists (album_id, artist_id)` and `track_credits (track_id, artist_id)`
- Replaces `track_artist` / `track_artist_id` entirely (migration backfills, then drops both columns)
- Artist page gains a "Singles, Remixes and Collaborations" section (replaces "Appears On")
- "Albums" section queries via `album_artists` instead of `album.artist_id`
- Credit management UI on album page: per-track `+` / chip-remove, owner-only, artist search against existing artists
- Album-level primary artist management at album header

### Key decisions

- **Two tables over one with a role field**: `album_artists` (primary album-level credit) + `track_credits` (featured/guest per track) rather than a single `track_credits (role)` table. Cleaner semantics — owning an album vs guesting on a track are different intents. Role field muddled into a single table creates edge cases (e.g., accidentally marking 13 of 14 tracks as co-artist).

- **Don't fight ID3 tags**: user doesn't want to retag MP3 files. Scanner keeps writing `album.artist_id` from the albumartist tag forever. Combined-credit artist entries ("i_o & Lights") are hidden from the artist list by changing the `GET /artists` query: show artists with `album_artists` entries OR direct unattributed albums. Once a combined-credit album is claimed via `album_artists`, the combined-credit artist has no qualifying albums and drops off the list naturally — no deletion needed.

- **`album.artist_id` stays for display only**: scanner keeps it as the authoritative display name for album cards. `album_artists` drives navigation. Cleaner than trying to suppress scanner writes.

- **RAC's *Boy* as the test case**: a producer album where every track has a different featured vocalist. Currently not supported by the VA-only compilations mechanism. The new credits system handles it cleanly (album_artists → RAC; track_credits → each vocalist).

- **Manual credits via UI, no scanner automation**: library isn't growing fast enough to warrant ID3 parsing of combined artist names (which would require heuristics for "A & B", "A feat. B", etc.).

### Gotchas

- **Temporary DB state**: during exploration, ran `UPDATE tracks SET track_artist_id = 149 WHERE id IN (2893–2906, 2915, 2916)` to tag Lights on the collab tracks. This doesn't currently surface on Lights' page (compilations endpoint requires VA album ownership). Migration 0008 will backfill `track_artist_id` → `track_credits`, so this state is handled automatically. No cleanup needed before the migration.

- **Edit was interrupted**: `artists.py` compilations endpoint edit was started but rejected before writing — the file is unchanged from before this session.
