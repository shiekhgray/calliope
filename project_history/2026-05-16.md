### PRD: Android Home Screen Redesign

**Goal**: Design spec for a significant restructure of the Android app's main navigation and home experience. No code written this session — PRD only.

**File**: `prd/android-home-screen.md`

**Context**: Phase 5 Android is feature-complete except for APK signing. This redesign improves the home UX before shipping by merging the Now Playing screen into the Home tab and adding a settings entry point.

**Design decisions** (captured via interactive Q&A):

- **Navigation**: Library tab removed. 3 tabs remain: Home / Search / Playlists. The `now-playing` route is eliminated — its content moves inside the Home tab as a conditional view.

- **Home tab — two states**:
  - `currentTrack == null` → shows artist library list (current `LibraryScreen` content). Top bar title: "Calliope".
  - `currentTrack != null` → shows full Now Playing content. Top bar title: "Now Playing".

- **Now Playing content** (when playing): album art → track info (title/artist/album, artist+album tappable for navigation) → scrubber → transport controls → radio chip → Previously Played (queue items before current, reversed) → Up Next (queue items after current) → Similar Tracks (existing similarity engine flow).

- **Stop button**: Added to the transport controls row between Pause/Play and Skip Next. Visually secondary (smaller icon, `onSurfaceVariant` tint). Behavior: `stopPlayback()` on PlayerViewModel — calls `player.stop()`, `player.clearMediaItems()`, clears `currentTrack`/`queue`/`queueIndex` in state. Home tab recomposes automatically to show Library. No navigation call needed.

- **Mini-player bar**: Unchanged (pause only). Tap behavior changes from `navController.navigate("now-playing")` to `selectedTab = 0` — switches to Home tab in-place.

- **Browsing while playing**: Library tab is gone. Users browse via Search tab only while something is playing. Stopping playback restores the Library list on Home.

- **Gear icon**: Always visible in Home top bar. Opens `ModalBottomSheet` with:
  1. **Change Password** — `AlertDialog` with 3 fields (current, new, confirm) → `POST /auth/change-password`
  2. **Sound Matching** — full 9-slider UI across 3 groups (Rhythm: Tempo/Beat Strength/Rhythm Regularity; Timbre: Brightness/Roughness/Warmth; Harmony: Key/Mode/Chord Complexity/Tonal Stability) → `PUT /auth/similarity-weights`
  3. **Sign Out** — confirm dialog → `tokenStorage.clear()` + navigate to login

**Files to be touched** (implementation not started):
- `ui/main/MainScreen.kt` — add Home tab content routing
- `ui/main/HomeScreen.kt` — new; wraps LibraryContent or NowPlayingContent
- `ui/player/NowPlayingScreen.kt` — deleted; content merged into HomeScreen
- `ui/library/LibraryScreen.kt` — extract inner list to `LibraryContent()`
- `playback/PlayerViewModel.kt` — add `stopPlayback()`
- `ui/navigation/NavGraph.kt` — remove `now-playing` route
- `ui/settings/SettingsSheet.kt`, `ChangePasswordDialog.kt`, `SoundMatchingSheet.kt` — new

**Blocker to verify before implementation**:
- Confirm `POST /auth/change-password` exists in the API router. Web has `ChangePasswordModal` so it likely does, but needs a grep check before building the Android dialog.

The `.claude/commands/` skill files had hardcoded `/home/gray/calliope/` paths throughout their
`!` inline bash commands. Since the project is now developed on both Linux (server) and Windows,
these were failing on Windows.

**Approach taken:**
- `coffee.md` / `beer.md`: switched all file path references to relative paths (e.g. `CLAUDE.md`,
  `.todo`, `project_history/YYYY-MM-DD.md`) — works because Claude always runs from project root.
- `api.md`, `web.md`, `android.md`, `similarity.md`, `history.md`: replaced `!` inline bash
  commands to use `REPO=$(git rev-parse --show-toplevel 2>/dev/null || echo /home/gray/calliope)`.
  Git returns a forward-slash path on both Linux and Windows (Git Bash), so bash file ops work.
- `import-music.md`: staging area changed from `/home/gray/Music/` → `~/Music/` (cross-platform
  via bash tilde expansion). Project path uses `git rev-parse` in exec commands.

During the rebase onto master, discovered that master had already refactored the same files
from `!` inline exec commands to "Read before starting" sections — a better pattern since it
uses Claude's Read tool rather than bash. Resolved conflicts by taking master's improved structure

### Android models synced with API changes (migrations 0009–0012)

The Android app's Kotlin models and `CalliopeApi.kt` were out of sync with several API changes
that landed on master:

**Breaking issues found:**
- `GET /artists/{id}/albums` now filters to `album_type='album'` only — singles/EPs silently
  disappeared from the Artist screen
- `GET /artists/{id}/singles` (new endpoint) was never called — Singles & EPs section entirely absent
- `Playlist` / `PlaylistDetail` models missing `view_mode`, `edit_mode`, `viewer_ids`, `editor_ids`
  added by migration 0012 (Moshi ignores unknown fields so no crash, but fields weren't available)
- `Album` / `AlbumDetail` missing `album_type` field (migration 0009)
- `CalliopeApi` missing: `getArtistSingles()`, `getArtistCompilations()`, `getTopTracks()`,
  `getPlaylistSimilar()`

**Fixes applied:**
- `LibraryModels.kt`: added `albumType: String = "album"` to `Album` and `AlbumDetail`
- `PlaylistModels.kt`: added `viewMode`, `editMode`, `viewerIds`, `editorIds` to `Playlist` and
  `PlaylistDetail` (all with defaults so existing parsing continues to work); added same fields to
  `CreatePlaylistRequest`
- `CalliopeApi.kt`: added `getArtistSingles()`, `getArtistCompilations()`, `getTopTracks()`,
  `getPlaylistSimilar()`
- `ArtistViewModel.kt`: now fetches singles in parallel alongside albums + top-tracks; `ArtistUiData`
  gains `singles: List<Album>`; `artistName` fallback chain: albums → singles → top-tracks
- `ArtistScreen.kt`: added "Singles & EPs" section below Albums in the grid

Committed: `android: sync models and endpoints with API changes`

### Key decisions

- **Relative paths over dynamic git detection for coffee/beer**: These skills tell Claude to Read
  files, and Claude's working directory is always the project root — relative paths are the
  simplest cross-platform solution. The `!` exec commands in other skills need `git rev-parse`
  because they run in a shell with an arbitrary CWD.

- **"Read before starting" over `!` inline exec**: Master's refactoring was correct. Telling Claude
  to Read files is more reliable than bash exec on skill load — works cross-platform, respects
  permissions, and shows the content in the conversation rather than at load time.

- **`Moshi ignores unknown fields` is not a silent risk**: Confirmed that `@JsonClass(generateAdapter = true)`
  (Moshi codegen) ignores unknown JSON fields and respects Kotlin default values for absent fields.
  So the API adding new fields to playlist/album responses did not crash the app — it just meant
  the new fields were unavailable.

### Gotchas

- `GET /playlists` and `GET /playlists/{id}` now require auth (migration 0012). The `AuthInterceptor`
  adds the bearer token to all requests, so this is transparent. But callers without a token
  (e.g. logged-out state) would get 401 — this is intentional and correctly handled by
  `TokenAuthenticator`.

- The `_playlist_card()` response shape is significantly richer than the old bare playlist object.
  The Android `Playlist` model doesn't consume `art_tracks`, `preview_tracks`, `top_genres`,
  `track_count` — these are ignored by Moshi. If we want to show rich playlist cards on Android
  (like the web does) we'd need to add those fields to the model.

- `play_count` is absent from playlist track objects (`_playlist_detail` response). Kotlin default
  of `0` kicks in. Correct behavior, but tracks always show 0 plays in a playlist context.
