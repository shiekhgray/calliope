- New `SimilarityWeightsModal` in web — 3 groups × 3 sliders (Tonal Character, Rhythm & Energy, Harmonic Texture); opened via "Sound Matching" in user menu
- `['me']` React Query key with `staleTime: Infinity` for initial slider values

### Key Decisions

- **DIM_SLICES slice boundaries**: `chord_movement` mapped to chroma variance (38–49) — chroma variance captures chord-to-chord change better than raw chroma mean for that axis. Not obvious from the name but intentional.
- **Tonnetz preprocessing**: `librosa.effects.harmonic(y)` applied before tonnetz calculation — reduces interference from percussive transients. This adds ~5–10% to indexing time but improves quality on drum-heavy tracks.
- **Weight scale**: `w / 5.0` makes the default (5) a neutral multiplier of 1.0; 0 = feature fully suppressed; 10 = double weight. Preserves existing behavior for users who haven't changed anything.
- **SimilarityWeightsModal `staleTime: Infinity`**: weights are user-initiated changes, not background data — no need to re-fetch unless the user just saved.

### Gotchas

- **Migration 0010 must run after rebuild**: The migration file has to be baked into the API image first. Running `alembic upgrade head` before rebuild silently no-ops (migration not found). Always rebuild before migrating.
- **Indexer port 8001 not accessible from host**: indexer container only reachable within the Docker network. Test via `docker compose exec api python3 -c "import urllib.request; ..."` — not via curl from host.
- **`np.atleast_1d(tempo)[0]`**: librosa 0.10.x returns either a scalar or 1-element array depending on the audio. Using `[0]` alone on a scalar raises an IndexError.

## Session 2

### Features Shipped

**Indexer bug fix — Vector(38) → Vector(60) in models.py**
- After migration 0010 expanded `track_vectors.feature_vector` to `vector(60)`, `indexer/app/models.py` still declared `Vector(38)`. The pgvector Python client validates dimensions client-side before the SQL INSERT fires — every insert failed with `ValueError: expected 38 dimensions, not 60`. The DB column was correct; only the indexer's ORM model was stale.
- Fix: updated `models.py` to `Vector(60)`, rebuilt indexer container, triggered re-index (2978 tracks, running in background).

**Genre Tagging — full feature**

API (8 new endpoints, all live):
- `GET /albums/{id}/genres` — committed genres for an album as `[{id, name}]`
- `GET /albums/{id}/genres/fetch` — Last.fm `album.getInfo` lookup; filter count < 10, top 5, lowercase, excludes already-applied genres
- `GET /albums/{id}/genres/suggest` — similarity k-NN tally; z-score + L2-normalize pipeline; walks nearest neighbors, stops at k tagged tracks (default 10) or m checked (default 50); returns top 3
- `POST /albums/{id}/genres` — auth required (both users); normalizes to lowercase; upserts genre; writes to all tracks in album
- `DELETE /albums/{id}/genres/{genre_id}` — auth required (both users); bulk delete from all album tracks
- `GET /genres?q=` — autocomplete filter added to existing endpoint; ILIKE, limit 20
- `GET /artists/{id}/genres/fetch` — Last.fm `artist.getTopTags`
- `GET /discover/{id}/genres/fetch` — Last.fm `album.getInfo` for a discovery entry; read-only, nothing persisted

Config: `LASTFM_API_KEY: str = ""` added to `config.py` and `.env.example`. Endpoints return `[]` gracefully when key is absent.

Web:
- `AlbumPage`: genre section below header — committed chips (with ✕ remove), pending suggestion chips (with ✓ accept / ✕ dismiss), Fetch/Suggest buttons, Add input with 300ms-debounced autocomplete dropdown
- `ArtistPage`: "Fetch genres" button in header (logged-in only); pending chips with per-chip dismiss; "Apply to all" fires `POST /albums/{id}/genres` for every album × genre with per-album progress counter
- `ReleasesPage` + `ArtistPage` Missing Releases: `ReleaseCardGenres` component — "Genres" button fetches on first click, toggles show/hide on subsequent clicks; read-only chips, no persistence
- New `web/src/components/ReleaseCardGenres.jsx`
- New CSS classes: `.genre-section`, `.genre-chips`, `.genre-chip`, `.genre-chip-pending`, `.genre-chip-btn`, `.genre-controls`, `.genre-add-wrap`, `.genre-autocomplete`, `.genre-pending-note`, `.genre-apply-progress`, `.genre-apply-done`
- New React Query key: `['album-genres', albumId]`

### Key Decisions

- **Genre POST/DELETE are auth-required, not owner-only.** Agent initially made them owner-only; corrected. Both users can tag — this is a shared music library and tagging is collaborative, not administrative.
- **`GET /albums/{id}/genres/suggest` has its own `DIM_SLICES` copy in `albums.py`**, not imported from `tracks.py`. Intentional: avoids cross-router coupling. Values are identical.
- **Pending suggestions are local state, not React Query.** They're volatile/discardable and user-initiated, so no caching makes sense.

### Gotchas

- **`indexer/app/models.py` must match the DB column dimension.** After any future vector expansion, update both the Alembic migration AND `indexer/app/models.py` and rebuild the indexer container. Failing to do so causes silent client-side `ValueError` on every insert — no DB error, just Python exceptions in the indexer logs.
- **Last.fm `LASTFM_API_KEY` is not yet in production `.env`.** Fetch endpoints return `[]` gracefully without it. Add `LASTFM_API_KEY=your_key` to `api/.env` and rebuild to enable.
