# Session — 2026-05-13

## Session 1

### Feature: Tab discard survival for PlayerContext

**Problem**: Chrome discards background tabs under memory pressure (or after ~a few minutes of inactivity with paused audio). Because the audio element is paused, Chrome has no signal that the tab is a live media player, so it reloads the page and wipes all React state — queue, current track, position gone.

**Fix** (`web/src/player/PlayerContext.jsx`, commit `ba8f87c`):

Two complementary mechanisms:

1. **Web Lock** — on mount, acquires an exclusive lock named `'calliope-player'` via `navigator.locks.request()` and holds it indefinitely (resolves only on component unmount). Chrome treats tabs with active locks as non-discardable, deprioritising them in the discard queue.

2. **sessionStorage persistence** — saves `{track, queue, queueIndex, progress: audio.currentTime}` to `sessionStorage` whenever `visibilitychange` or `pagehide` fires (both fire before Chrome discards). On mount, if saved state exists:
   - Initial React state is seeded from it (queue, currentTrack, queueIndex, progress).
   - Refs (`queueRef`, `queueIndexRef`, `currentTrackRef`) are also seeded so event handlers are consistent from the first render.
   - `isPlaying` is set to `false` (not `null`) so PlayerBar renders the track immediately.
   - `audio.src` is set and `audio.load()` called; a one-time `loadedmetadata` listener seeks to the saved position.
   - `playTrack()` clears saved state (`sessionStorage.removeItem` + `saved.current = null`) to prevent a stale restore racing a fresh manual play.

**Key design notes**:
- Saving on `visibilitychange` (not `ontimeupdate`) keeps writes cheap — one write per tab hide, not 60/s.
- `pagehide` catches navigate-away and tab close; `visibilitychange` catches tab switches (which precede discard).
- The restore does not autoplay — browser policy blocks autoplay on reloaded tabs anyway, and `isPlaying: false` is the correct "loaded but paused" state.
- `saved` is a `useRef` (not state) so reading it in `useEffect` doesn't trigger re-renders.

## Session 2

### Feature: Playlist Permissions

**Goal**: Per-playlist view and edit access control. Previously all playlists were fully public and any authenticated user could mutate any playlist.

**Migration 0012** (`api/alembic/versions/0012_add_playlist_permissions.py`):
- Added `view_mode VARCHAR(10) NOT NULL DEFAULT 'everyone'` and `edit_mode VARCHAR(10) NOT NULL DEFAULT 'owner'` to `playlists`
- Created `playlist_viewers (playlist_id, user_id)` and `playlist_editors (playlist_id, user_id)` join tables with cascade-delete FKs
- Applied: `0011 → 0012` ran clean; existing playlists got default values — no data loss

**API changes** (`api/app/routers/playlists.py`, new `api/app/routers/users.py`):
- Added `can_view()` and `can_edit()` permission helpers; edit implies view
- `_playlist_summary()` serializer returns `view_mode`, `edit_mode`, `viewer_ids`, `editor_ids`, `owner_id` on every playlist response
- `GET /playlists` and `GET /playlists/{id}` now require Bearer auth and enforce `can_view`; unauthenticated → 401
- `PUT /playlists/{id}`: any editor can update title/description; only owner can update permission fields (non-owner permission fields silently ignored)
- `DELETE /playlists/{id}`: owner-only
- Track mutations (`POST/DELETE/PUT tracks`): all check `can_edit`
- `GET /playlists/{id}/similar`: checks `can_view`
- New `GET /users` endpoint (auth required) returns `[{id, username}]` — used by frontend user picker
- `_sync_viewers()` / `_sync_editors()` replace ACL sets atomically via SQLAlchemy core delete + insert

**Models** (`api/app/models.py`):
- `playlist_viewers` and `playlist_editors` defined as SQLAlchemy `Table` objects
- `Playlist.viewers` and `Playlist.editors` relationships via secondary

**Web changes**:
- `PlaylistPage.jsx`: gear ⚙ button (owner-only) toggles inline permissions panel; panel has "Who can view" and "Who can edit" sections each with three radio buttons (Only me / Specific users / Everyone); "Specific users" mode shows checkbox list of all non-owner users from `GET /users`; Save fires `PUT /playlists/{id}`; "by {username}" subtitle shown to non-owners; Rename/DnD/remove-track all gated by `canEdit`; Delete gated by `isOwner`
- `PlaylistsPage.jsx`: delete button only renders when `pl.owner_id === userId`
- `['users']` React Query key added (staleTime: default 30s)
- CSS: `.permissions-panel`, `.permissions-section`, `.permissions-section-title`, `.permissions-radio-group`, `.permissions-user-list`, `.permissions-save-row`, `.gear-btn`, `.playlist-owner-subtitle`

**Key note — "Ellie's playlist"**: There was a saved memory note to reassign it to user `rose`. Confirmed: `rose` (id=4) already exists and already owns that playlist — no SQL fixup needed.
