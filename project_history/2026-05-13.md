# Session — 2026-05-13

## Session 1

### Feature: Tab discard survival for PlayerContext

**Problem**: Chrome discards background tabs under memory pressure (or after ~a few minutes of inactivity with paused audio). Because the audio element is paused, Chrome has no signal that the tab is a live media player, so it reloads the page and wipes all React state — queue, current track, position gone.

**Fix** (`web/src/player/PlayerContext.jsx`, commit `ba8f87c`):

Two complementary mechanisms:

1. **Web Lock** — on mount, acquires an exclusive lock named `'calliope-player'` via `navigator.locks.request()` and holds it indefinitely (resolves only on component unmount). Chrome treats tabs with active locks as non-discardable, deprioritising them in the discard queue.

2. **sessionStorage persistence** — saves `{track, queue, queueIndex, progress: audio.currentTime}` to `sessionStorage` whenever `visibilitychange` or `pagehide` fires (both fire before Chrome discards). On mount, if saved state exists:
   - Initial React state is seeded from it (queue, currentTrack, queueIndex, progress).
   - Refs (`queueRef`, `queueIndexRef`, `currentTrackRef`) are also seeded so event handlers are consistent from the first render.
   - `isPlaying` is set to `false` (not `null`) so PlayerBar renders the track immediately.
   - `audio.src` is set and `audio.load()` called; a one-time `loadedmetadata` listener seeks to the saved position.
   - `playTrack()` clears saved state (`sessionStorage.removeItem` + `saved.current = null`) to prevent a stale restore racing a fresh manual play.

**Key design notes**:
- Saving on `visibilitychange` (not `ontimeupdate`) keeps writes cheap — one write per tab hide, not 60/s.
- `pagehide` catches navigate-away and tab close; `visibilitychange` catches tab switches (which precede discard).
- The restore does not autoplay — browser policy blocks autoplay on reloaded tabs anyway, and `isPlaying: false` is the correct "loaded but paused" state.
- `saved` is a `useRef` (not state) so reading it in `useEffect` doesn't trigger re-renders.
