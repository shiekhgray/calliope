## Session 1 — Loose FLAC single import

### Shipped
Support for importing Qobuz singles, which are sold as bare `.flac` files (no zip,
no folder structure). Committed + pushed to master as `b9f5cca`.

Three layers changed:

1. **Host script** (`scripts/qobuz_import.py`) — added a `--loose <track.flac> [cover.jpg]`
   mode. Mirrors `amazon_import.py`'s loose path (reads albumartist/album/title tags via
   mutagen, resolves primary artist from collaboration tags, optional cover→Folder.jpg)
   but combines it with the existing FLAC→MP3 V0 transcode. `main()` was restructured:
   positional arg renamed `zips`→`files`, added `--loose` flag + routing. Album-zip path
   unchanged.

2. **Web upload** (`api/app/routers/import_music.py`) — `.flac` previously fell through to
   the zip handler and failed ("Not a valid zip file"). Now `.flac` routes to
   `_process_audio_single`, which transcodes FLAC→MP3 (temp file + ffmpeg) before writing.
   Added `LOOSE_SINGLE_EXTENSIONS` constant. `_process_audio_single` now also uses
   `Path(filename).name` (path-traversal hardening) instead of raw filename.

3. **Frontend** (`web/src/pages/ImportPage.jsx`) — added `.flac` to the accept regex,
   error message, `<input accept>`, and dropzone sub-label.

### Auto-tagging singles as 'single'
The owner asked that `--loose` imports automatically get `album_type='single'`. Since the
host script (runs on host, no DB access) and the scanner (runs in container) only share the
filesystem, the chosen mechanism is a **hidden `.album_type` marker file** dropped in the
album dir containing `single`.

- `api/scripts/scan.py`: new `read_album_type(album_dir)` helper + `ALBUM_TYPE_MARKER` /
  `VALID_ALBUM_TYPES` constants. `upsert_album` gained an `album_type` param applied
  **only on album creation** — a rescan never clobbers a later manual change via
  PATCH /albums/{id}/type (the AlbumPage type-cycle pill).
- Both the host `--loose` path and the web `_process_audio_single` path drop the marker.
- Marker has an empty filename suffix (`Path(".album_type").suffix == ""`), so the scanner's
  track loop (filters by AUDIO_EXTENSIONS) and `find_cover_art` (filters by `.jpg`) both
  ignore it — verified before relying on it.

### Key decisions
- **Transcode FLAC→MP3 rather than store lossless.** Matches how the rest of the library is
  stored; the no-transcode constraint in CLAUDE.md is about *streaming*, not import. Flagged
  to owner as reversible if they ever want lossless singles (scanner already supports .flac).
- **All loose singles get the marker, not just FLAC.** A loose `.mp3`/`.m4a` uploaded via web
  now also tags `single` (previously came in as `album`). Done for consistency with the host
  `--loose` convention and to avoid "flac singles tagged, mp3 singles not." Flagged to owner;
  offered to gate to FLAC-only if undesired — no objection given.
- Marker applies on creation only → existing library albums are unaffected; only future
  imports change.

### Gotchas discovered
- The web `/import/upload` path is **completely separate** from the host `qobuz_import.py`
  script. Supporting FLAC in one does nothing for the other — both had to be changed.
- `qobuz_import.py` `main()` bails if `--music-root` doesn't already exist, so the throwaway
  test needed `mkdir -p` on the lib dir first (the real `/backup/calliope/music` always exists).

### Infra applied
- Rebuilt + restarted the API image twice (`docker compose build api && docker compose up -d api`)
  — `scan.py` and `import_music.py` are baked into the image. No migration needed (`album_type`
  already exists from migration 0009).
- No nginx/DB schema changes.
